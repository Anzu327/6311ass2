# 两人云端协作

1. 拥有者邀请搭档作为 Collaborator，搭档接受邀请。
2. 两人各自在同一仓库创建自己的 Codespace；这是两个独立开发环境，不是同时编辑同一个文件。
3. 创建功能分支：你用 `feature/experience`，朋友用 `feature/feed-content`。
4. 运行 `npm run dev`，打开 5173 的预览。两个人都确认可运行；无需 API 密钥。
5. 提交和 push 后创建 PR，描述体验变化，附截图。另一人预览并检查自动测试。
6. 合并后两人切回 main，`git pull --ff-only` 同步。开始下一轮工作前再建新分支。

如果两人都改同一文件，先沟通内容范围。冲突时保留双方有价值的修改，解决后重新运行检查；不要强制推送覆盖搭档。

`src/content.ts` 专门留给内容合作：保持三个身份和每个身份六条帖子，第四条为虚构商业广告，最后两条表现推荐收窄。修改文案不需要改摄像头实现。

PR 的 CI 只证明代码检查通过，不能代替两台设备的摄像头与移动端验证。两个真实 Codespaces 的创建和启动需各自 GitHub 账户操作，代理的本地测试不会冒充这个验证。
